01 / The work

See the shortfall before the commitment.

Several affordable-looking offers can become unaffordable when their dates overlap. Planning needs the starting balance, expected deposits, unpaid installments, minimum buffer and existing reservations on one timeline. SettleLift’s prototype makes those assumptions explicit.

02 / The process

How the work connects.

  1. Set an as-of date, hypothetical opening balance and minimum buffer. Enter the deposit events that should be included in the scenario.
  2. Inspect the running balance against unpaid obligations. Review the first projected shortfall and the effect of overdue installments before adding another commitment.
  3. Place a conservative local offer hold, compare the remaining scenario funds and release the hold when appropriate. Existing schedules and holds must not count the same obligation twice.
03 / Context & decisions

The details that matter.

The planner uses integer cents for calculations and reconciles installment totals. Month-end dates and leap years are tested. The display is a scenario, not a bank statement: manual deposits are not verified transactions, and browser holds are not multi-user reservations. Production funding requires provider reconciliation, server-side locks, retry-safe events and return handling before any movement of money.

05 / Common question

Does SettleLift hold the consumer’s money?

The current prototype holds and transfers no money. A future financial connection must use an authorized provider and verified instructions. No payment rail is activated by this website.
