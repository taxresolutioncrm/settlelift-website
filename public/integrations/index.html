01 / The work

A clear status for every connection.

A portal, a calling provider and a payment network solve different problems. SettleLift keeps these connection types separate so a proposed integration cannot be confused with a live operating relationship. No bank, collector or funding provider is connected by this website.

02 / The process

Connect, authorize, then verify.

  1. Choose the company’s authorized communication and financial providers. Establish what data each connection needs and who may activate it.
  2. Configure credentials only through protected server settings. Keep secret and service-role keys out of public browser files.
  3. Test delivery, identity, event matching, duplicate handling, reversals and disconnection before enabling the workflow for real records.
03 / Context & decisions

The details that matter.

The prepared browser gateway pins its destination to an explicit Supabase project and requires a signed-in session supplied by the future Auth integration. It limits the allowed workflow endpoints and refuses redirects. Production provider adapters still need webhook verification, stable external identifiers and clear failed/retry states. QuickBooks is a planned accounting connection; e-sign, phone, SMS, email and fax remain separate activation work. No partnership or certification is implied by listing an integration category.

05 / Common question

Can SettleLift connect to every creditor automatically?

No. External APIs and payment networks require provider access and approval. An invited representative portal is a separate capability from a direct integration.
