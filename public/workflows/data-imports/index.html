01 / The work

Review before committing the rows.

A migration can create lasting confusion if columns, amounts or people are matched incorrectly. SettleLift’s import prototype uses an explicit dry run, highlights errors and requires choices for duplicates instead of silently rewriting existing clients.

02 / The process

How the work connects.

  1. Paste a CSV with the supported headers and inspect the parsed rows. Quoted names, row widths and currency values are checked.
  2. Resolve validation errors and unknown columns. Review in-file duplicates and possible existing-client matches explicitly.
  3. Commit the reviewed rows and inspect the resulting client/debt relationships. Keep the source file and migration evidence for a future audited import.
03 / Context & decisions

The details that matter.

The current tool is a pasted-CSV prototype with a limited field mapping. It does not migrate a competitor’s entire database, documents, signatures or payment ledger. A production migration needs a source inventory, documented mapping, rollback plan, batch counts and reconciliation. Historical payment evidence must not be recreated as a manual “paid” mark. Legal entities and creditor aliases also require reviewed matching.
